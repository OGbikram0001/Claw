## 2024-05-18 - Chat List Re-render Cascades
**Learning:** The chat view features complex list items rendered via `map`. The frequent updates to state in the parent component (e.g., `inputText` changing on every keystroke) caused entire `O(N)` list re-renders because the callback references for tools and approvals changed, propagating downward despite no changes to the actual message contents. This is an architectural bottleneck when state is highly co-located.
**Action:** Applied `useCallback` to `toggleTool`, `handleApprove`, and `handleReject` in `frontend/app/index.tsx` to preserve reference stability, and wrapped all child message components in `frontend/src/Bubbles.tsx` with `React.memo`, utilizing a custom comparison function for tools expansion state to skip unnecessary re-renders. This brings re-renders down to `O(1)` per keystroke.
